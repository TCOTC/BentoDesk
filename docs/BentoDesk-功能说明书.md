# BentoDesk：轻量级 Windows 桌面整理工具——功能说明书

> 当前版本：1.3.0 | 开发者：Tianyu Zhu | 开源协议：GPL-3.0
> 技术栈：WinUI 3 + .NET 10 + Windows App SDK 2.2
> 适用系统：Windows 11（64 位）

---

## 一、BentoDesk 是什么

BentoDesk 是一款 Windows 11 桌面整理工具。它不替换你的桌面，而是在原生桌面之上补一层整理能力——用轻量的桌面"盒子"来收纳文件、映射文件夹和控制音乐。

核心理念可以一句话概括：**文件仍然是普通文件，盒子只是帮你收纳和快速访问。** 你不会被绑死在 BentoDesk 里——卸载它，你的文件还在原来的文件夹中，原封不动。

这与 Fences 等传统桌面整理工具的思路不同。Fences 倾向于"接管桌面"，把所有桌面图标纳入自己的管理体系；BentoDesk 更克制，它只在桌面上放置若干独立的小窗口（盒子），每个盒子有明确的功能边界，桌面其余部分完全不受影响。

## 二、安装

### 安装包

从官网或 GitHub Releases 下载 Inno Setup 构建的 exe 安装包（如 `BentoDesk_Setup_1.3.0_x64.exe`）。安装包自带独立更新器，可在应用内检查并安装新版本。

### 安装过程

安装到当前用户目录（非 Program Files），**不需要管理员权限**。这是一个刻意的设计——以管理员权限运行的桌面工具会导致资源管理器的拖拽功能失效，因此 BentoDesk 选择用户级安装。

安装时会自动检测两个运行时依赖：

- .NET 10 Desktop Runtime x64
- Windows App Runtime 2.2 x64

如果系统缺少，安装器会联网下载并安装。

覆盖安装会保留已有的设置、盒子配置；桌面上的实际文件本来就不在安装目录里。如果旧版本装在 Program Files 下，安装器会自动迁移到用户目录。

### 卸载

卸载前会先停止运行中的 BentoDesk，然后询问是否删除本地数据（位于 `%LocalAppData%\BentoDesk`）。桌面文件和映射文件夹中的用户文件不会被静默删除。

## 四、托盘菜单——日常控制中心

引导结束后，BentoDesk 常驻系统托盘。你不和盒子直接交互时，它安静地待在托盘区。

### 左键单击：显示/隐藏全部盒子

智能判断当前状态：如果盒子已经显示，且前台窗口是桌面、任务栏或 BentoDesk 自身，则隐藏全部盒子；否则唤起全部盒子到顶层。

这个操作也可以用全局快捷键（默认 F7）触发。日常使用中最频繁的动作就是这个——需要盒子时唤起，不需要时收起，桌面瞬间回到干净状态。

## 五、主要盒子类型

盒子是 BentoDesk 的核心交互单元。每个盒子是一个独立的桌面小窗口，有自己的标题栏、内容和操作菜单。当前主要包括文件盒子与音乐盒子；其它功能盒子也可按需启用。

> 📸 **[配图 8]** 盒子并列展示——一张图里同时展示文件盒子与音乐盒子。

### 5.1 文件盒子

文件盒子是 BentoDesk 最核心的盒子类型，用于收纳和整理桌面文件。它有两种来源：

**收纳盒子**

整理仍留在用户桌面目录中的文件。未分类默认盒显示尚未归属的桌面文件；分类盒显示已归属到该盒的桌面文件。拖入分类盒只会改变归属；从非桌面位置拖入时，会先按设置复制或移动到桌面，再纳入显示。

创建方式：托盘菜单 → 创建盒子 → 选择文件盒子。

**映射盒子**

指向一个已有的文件夹（可以是任意位置）。映射盒子直接展示该目录内容，不另建副本。适合那些你不想移动但希望在桌面上快速访问的文件夹。

创建方式：托盘菜单 → 映射文件夹 → 选择目标文件夹。

> 💡 **收纳 vs 映射的区别**：收纳盒子整理桌面上的文件归属；映射盒子直接展示你指定的已有文件夹。

**文件操作**

| 操作 | 方式 |
|------|------|
| 拖入文件 | 从资源管理器或桌面拖文件到盒子，默认复制，可在设置中改为移动 |
| 拖出文件 | 从盒子拖文件到资源管理器或其他位置 |
| 双击打开 | 双击文件项打开（可在设置中关闭此行为） |
| 空格预览 | QuickLook 已运行时，选中文件后按 Space 打开或关闭预览 |
| 右键菜单 | 复制、剪切、重命名、删除、在资源管理器中显示 |
| 多选 | 框选或 Ctrl/Shift 点击多选，支持批量复制/剪切/删除 |
| 排序 | 名称 / 大小 / 类型 / 修改日期 |
| 视图切换 | 图标视图 / 列表视图（列表视图可显示详情） |

**自动叠放**

自动叠放只改变盒子内的展示，不移动真实文件。可以按文件类型或日期分组，也可以创建自定义扩展名规则。自定义规则从上到下匹配，支持拖动调整优先级、实时预览命中文件、设置形成叠放所需数量、叠放内排序，以及未匹配文件保持散开或收入“其他”。展开叠放后，文件仍在当前盒子内散开展示。

> 📸 **[配图 9]** 文件盒子截图——展示图标视图下的文件盒子，包含若干文件项和标题栏操作按钮。

> 📸 **[配图 10]** 文件盒子右键菜单——展示排序、视图切换等菜单项。

### 5.2 音乐盒子

音乐盒子是一个桌面音乐控制面板。注意：它本身不是播放器，而是对系统正在播放的音乐进行控制。

**功能**

- 播放控制：上一首 / 播放暂停 / 下一首
- 播放模式切换
- 系统音量调节
- 封面居中裁剪展示
- 歌名跑马灯（文字过长时滚动）
- 封面平滑切换动画

**自适应布局**

默认会根据盒子尺寸自动切换布局；也可在设置中强制使用封面模式或控制模式。自动模式在宽度小于 180px 时切换为封面优先的紧凑布局，只显示封面和基本控制，隐藏歌名等次要信息。

**氛围取色**

可开启"封面氛围"功能，根据当前播放歌曲的封面颜色，为盒子背景生成柔和的色调，营造沉浸感。

**悬停动效**

鼠标悬停在封面上时有轻量的动效反馈。

> 📸 **[配图 12]** 音乐盒子截图——展示封面、歌名、播放控制按钮和氛围取色背景。

> 💡 音乐盒子是**单例盒子**——全局只能创建一个。重复创建不会生成新的，而是聚焦到已有的那个。

## 六、盒子窗口交互

所有类型的盒子共享一套统一的窗口交互行为。

### 标题栏

每个盒子顶部有一个标题栏，显示盒子名称。标题栏支持以下操作：

- **拖动移动**：按住标题栏拖动盒子到任意位置
- **双击重命名**：双击标题栏进入重命名模式
- **右键菜单**：重命名 / 切换视图 / 排序 / 锁定位置 / 锁定大小 / 添加盒子 / 更多 / 删除
- **悬停操作按钮**：鼠标移到标题栏时显示快捷操作按钮（可在设置中配置显示哪些按钮：锁定位置、锁定大小、添加、更多、删除）

### 调整大小

拖动盒子边缘可以调整大小。调整过程中有**对齐引导线**——当盒子边缘接近其他盒子边缘或屏幕工作区边缘时（8px 阈值），会出现高亮对齐线，帮助你对齐盒子。可在设置中开关此功能。

盒子最小尺寸为 150×150。

### 位置锁定

可以锁定盒子的位置和大小。锁定后无法拖动或调整，防止误操作。需要解锁后才能再次移动。

> 📸 **[配图 15]** 盒子调整大小时的对齐引导线——展示两个盒子边缘对齐时的高亮线效果。

### 胶囊模式

开启“允许盒子收起”后，盒子可以收起为紧凑胶囊。常用选项包括：

- **展开方式**：保持展开、点击展开或悬停展开。悬停仅由标题中间区域触发，图标与操作区保留给拖动和按钮，减少误展开。
- **收起后显示**：关键信息、简要摘要或仅图标和标题；可隐藏敏感正文。
- **宽度关系**：保持同宽（胶囊和展开盒子宽度一致）或独立调整。
- **排列方式**：独立摆放，或组合成可整体移动和排序的栏；组合栏可悬浮或贴到屏幕边缘。
- **动画与响应**：快速、标准、舒缓、关闭或自定义动画；悬停响应支持灵敏、平衡、防误触和自定义。

盒子会以胶囊所在边角为展开锚点，并结合屏幕剩余空间选择方向。拖入文件、文本或附件时会临时展开，松开或离开后恢复原状态，不会修改原有展开尺寸或胶囊位置。单个盒子可覆盖全局展开方式、宽度和位置，这些覆盖项可在设置中集中恢复为跟随全局。

### 层级管理

盒子固定在桌面图标层：位于桌面图标上方、普通应用窗口下方，不会被临时置顶。托盘或全局快捷键用于显示/隐藏盒子，而不是把盒子抬到其他窗口之上。

### 标题模式

可分别配置"显示类盒子"（文件）和"交互类盒子"（音乐）的标题显示模式：

- **标准**：正常显示标题栏
- **紧凑**：缩小标题栏高度
- **覆盖**：标题栏覆盖在内容上方
- **隐藏**：完全不显示标题栏

### 多显示器支持

盒子记录了创建时的显示器和位置锚点（左上/右上/左下/右下）。当分辨率变化或显示器拓扑发生变化时（如外接/断开显示器），盒子会根据锚点自动恢复到合理位置。

### 7.7 维护（Maintenance）

## 八、如何用 BentoDesk 整理桌面

这一节不是功能罗列，而是基于 BentoDesk 的设计理念，给出实际的使用建议。

### 核心原则

BentoDesk 的设计哲学是"不替换桌面，只补一层"。意思是：桌面只放当前正在用的东西，其他都收进盒子；盒子可以随时唤起和隐藏，文件始终是普通文件，始终在真实文件夹里，不会和 BentoDesk 绑死。

### 推荐工作流

**第一步：按用途创建收纳盒子**

打开托盘菜单 → 创建盒子，为不同用途创建文件盒子。比如：

- 📁 工作文件——日常工作文档
- 📁 下载临时——从浏览器下载的东西先丢这里
- 📁 截图——截图工具的默认保存目标
- 📁 项目素材——当前项目的图片、资料
- 📁 待处理——需要后续跟进的文件

每个盒子背后是一个真实文件夹。默认拖入会复制文件；如果希望桌面原文件在收纳后消失，可把拖入行为改为“移动”。

**第二步：对不想移动的文件夹用映射盒子**

有些文件夹你不希望移动（比如项目目录、代码仓库），但又想在桌面上快速访问。用托盘菜单 → 映射文件夹，把它映射成桌面盒子。映射盒子只读展示，不碰原文件。

**第三步：放置功能盒子**

根据需要开启功能盒子：

- 放一个**音乐盒子**，工作时控制播放不用切窗口。

**第四步：善用快捷键**

记住全局快捷键（默认 F7）。工作时按一下唤起全部盒子，用完再按一下隐藏。桌面在"工作模式"（盒子全开）和"干净模式"（盒子全收）之间一键切换。

**第五步：按用途命名分类盒**

比起「PDF」「图片」，更推荐「待处理」「本周项目」这类用途型命名。需要固定某个已有项目目录时，再用映射盒子。

> 📸 **[配图 25]** 整理后的桌面效果——展示一个"工作模式"下的桌面，几个收纳盒子有序排列，角落有音乐盒子。

### 注意事项

1. **不要把所有文件塞进一个盒子**。盒子是分类工具，一个盒子对应一个用途。盒子太多反而乱，建议 4-8 个文件盒子。
2. **映射盒子不会改变文件位置**。收纳盒子整理的是桌面文件归属；非桌面来源拖入时可在设置里选择先复制或移动到桌面。
3. **音乐盒子是单例**。全局只能有一个，重复创建不会生成新的。
4. **卸载 BentoDesk 不会丢桌面文件**。收纳盒子里的文件本来就在用户桌面目录中，卸载只影响程序和配置。
5. **如果拖拽不工作**，去设置 → 维护 → 拖拽异常诊断，一键修复。常见原因是程序以管理员权限运行（BentoDesk 默认用户级运行，一般不会出这个问题）。

## 九、技术概览

> 本节面向技术人员，普通用户可跳过。

### 技术栈

| 层面 | 技术 |
|------|------|
| UI 框架 | WinUI 3 + Windows App SDK 2.2 |
| 运行时 | .NET 10 |
| MVVM | CommunityToolkit.Mvvm（源生成器模式） |
| UI 控件 | CommunityToolkit.WinUI |
| 托盘图标 | H.NotifyIcon.WinUI |
| 打包 | Inno Setup（Direct）/ MSIX（Store） |
| 多语言 | 自研 LocalizationService（JSON 字典） |

### 架构

采用 MVVM 分层架构：

- **Models**：AppSettings、WidgetConfig、FileStackCustomRule 等数据模型
- **ViewModels**：按盒子和设置领域拆分，音乐与文件叠放分别维护状态
- **Views**：窗口生命周期、菜单、拖放、选择、调整大小、胶囊状态和标题交互按职责拆分为 partial class
- **Services**：WidgetManager、文件操作、附件、自动叠放、备份恢复、QuickLook、音乐会话、提醒、设置、主题和全局热键等
- **Helpers**：Win32 互操作、Shell 上下文菜单、图标提取、剪贴板等

### 分发

通过 Inno Setup 安装包分发，应用内更新由 `BentoDesk.Updater` 与安装包覆盖安装完成。

### 项目规模

- 主应用按窗口、内容、设置和服务职责拆分，避免继续堆积超大界面类
- 自动化测试覆盖数据安全、附件、叠放、胶囊边界、设置迁移和核心盒子行为
- Direct 安装器不内置 .NET 与 Windows App Runtime 安装程序，缺失时按需下载
