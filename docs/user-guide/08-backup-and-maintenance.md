# BentoDesk 备份、恢复与数据维护指南

BentoDesk 长期保存盒子配置和大量个性化设置。开始长期使用后，应尽早理解哪些内容属于 BentoDesk 数据，哪些仍然需要独立文件备份。

> [图片占位：设置中的备份与恢复页面。展示导出、恢复、立即创建快照、快照列表和状态信息]

## 备份保护什么

BentoDesk 数据备份主要覆盖

- 应用设置
- 盒子配置、位置和尺寸
- 恢复所需的清单和完整性摘要

备份不会自动复制所有外部映射目录，也不等于整台电脑备份。

如果文件盒子映射了 `D:\Projects`，BentoDesk 备份会保护映射关系和盒子配置，但项目目录本身仍应由版本控制、云盘或其他备份方案保护。

## 手动导出 ZIP

进入 `设置 > 诊断与维护 > 备份与恢复`，选择导出并指定保存位置。

BentoDesk 不会直接一边读取正在变化的数据目录一边压缩。它会

1. 创建稳定的临时快照。
2. 检查源文件在复制过程中是否变化。
3. 验证快照中的关键数据。
4. 从快照生成 ZIP。
5. 写入包含文件 SHA-256 的清单。
6. 清理临时目录。

如果数据在复制过程中持续变化，BentoDesk 会重试或停止，而不是静默生成前后状态混杂的压缩包。

## 恢复备份

恢复前先关闭正在编辑的任务，不要同时进行大批量文件拖放。

BentoDesk 会先检查

- 备份结构是否受支持。
- 必需文件是否存在。
- 清单中的文件摘要是否匹配。
- 数据能否通过基本解析和安全检查。

通过后，恢复数据进入暂存区域，并使用能够跨重启继续的流程应用。恢复前还会创建保护性快照。

恢复会修改当前 BentoDesk 配置和记录。重要状态下建议先手动导出当前数据，再恢复旧备份。

## 自动快照

BentoDesk 最多保留 7 份每日自动快照。同一天已存在新快照时，不会因为每次打开设置就重复创建。

设置页面可以

- 查看快照时间、类型和状态
- 立即创建快照
- 删除受管理的快照
- 打开快照目录
- 识别不可读取或损坏的快照

自动快照是快速回退保护，不应成为唯一备份。硬盘损坏或整个用户目录丢失时，同盘快照也可能一起消失。

## 恢复前快照

每次应用恢复前，BentoDesk 会创建恢复前快照，最多保留 5 份。

它的作用是，当恢复文件本身正确，但你后来发现选错版本时，仍然有机会回到恢复前状态。

## 桌面文件和应用数据目录

收纳盒子整理的是仍留在用户桌面目录中的文件；映射盒子指向你指定的已有文件夹。这些实际文件都不在 BentoDesk 备份范围内。

应用数据目录保存配置和快照等内部数据，通常位于用户本地应用数据区域（`%LocalAppData%\BentoDesk`）。它更像 BentoDesk 的状态与数据库空间，而不是用户文件仓库。

不要在 BentoDesk 运行时手动编辑内部 JSON。需要迁移时，优先使用备份与恢复。

## 全局重置和功能盒子重置

### 全局重置

恢复外观、交互等偏好设置，不应删除普通文件。语言、开机启动和功能盒子开关等部分项目会按产品保护规则保留。

### 功能盒子重置

针对音乐等单独功能，可能清除对应数据和设置，需要二次确认。

两者不是同一个操作。

看到「重置」前，先读确认对话框中写的是偏好还是数据。

## JSON 损坏恢复

BentoDesk 对关键 JSON 数据提供弹性读取和回退机制。发现主文件无法解析时，会尝试使用安全副本或恢复路径，而不是直接用空数据覆盖。

如果界面提示数据损坏

1. 不要反复新建同名内容。
2. 完全退出 BentoDesk。
3. 先复制整个应用数据目录作为现场备份。
4. 使用维护工具或已知良好 ZIP 恢复。
5. 无法判断时保留文件并提交日志，不要自行删除。

## 升级前检查清单

重要版本升级前建议

1. 导出手动 ZIP 备份。
2. 确认备份文件大小不是 0，页面显示完整性正常。
3. 确认桌面与映射目录中的重要文件可独立访问。
4. 对映射的项目目录执行独立备份。
5. 完全退出 BentoDesk，或让新版安装器自动关闭旧进程。
6. 覆盖安装后检查盒子位置和设置。

## 推荐备份策略

- 日常依赖自动快照做短期回退。
- 每次大版本升级前导出手动 ZIP。
- 每周或每月把手动 ZIP 复制到另一块磁盘或云盘。
- 桌面文件和映射目录使用独立文件备份。

BentoDesk 备份保护 BentoDesk 的工作状态。完整数据安全仍然需要多位置备份。
